どんなアプリか

トレーディングカードの「抽選」「予約」「先着販売」の情報は、販売店ごとの告知や、X の投稿に散らばっています。気づいたときには、締切が過ぎている。トレカダッシュは、全国の販売店やオンラインストアの告知を集めて、応募・購入できるページへすぐ移動できる形で、お届けするアプリです。

主な機能

フィード

受付中の抽選・予約・先着販売を、ジャンルや販売形式で絞り込んで確認できます。

通知

フォローした商品やジャンルに、新しい情報が出たら、すぐにお知らせします。

締切カレンダー

抽選の締切や、結果の発表日を、日付ごとに一覧できます。応募漏れを防ぐための画面です。

応募管理

応募した抽選の結果や、購入を記録できます。

マップ

店頭の入荷や抽選の情報を、利用者どうしで共有できます。

今日の運試し

毎日、無料で挑戦できるおみくじです。購入や課金は要りません。

対応しているジャンル

ポケモンカードゲーム、遊戯王、ONE PIECE カードゲーム、ユニオンアリーナ、ロルカナ、デュエル・マスターズ、ドラゴンボール、ガンダム、マジック：ザ・ギャザリング、ヴァイスシュヴァルツ、名探偵コナン、ホロライブ、デジモン、ハイキュー!! バボカ!!、パルワールドの 15 ジャンルです。

トレカダッシュ Pro（有料）

基本の機能は、無料で使えます。Pro では、次のことができるようになります。

  • 商品フォロー、キーワードアラート、除外キーワードが、無制限になる。
  • 先着・ゲリラ販売の通知が、いちばん早く届く（無料版は、約 15 分遅れ）。
  • 現在地から近い店舗に、絞り込める。
  • 通知履歴の全期間の閲覧、応募の統計、カレンダーの書き出し、CSV の出力。
  • 購入の記録から、資産評価額と損益を、グラフで管理する。
  • 広告を表示しない。

作りについて

画面は SwiftUI で作っています。情報を集める側は、Firebase（Cloud Functions と Firestore）と、自前のサーバーで動いています。販売ページを定期的に取得して、記事が「どの商品の話か」を照合して（AI を一部に使っています）、出品価格が妥当かを審査する。この流れを、毎日、回しています。

作る途中で測ったことや、間違えたことは、Notes に書いています。下の「この作品の記録」から、読めます。

よくある質問

どこで手に入りますか？

App Store で配信している iPhone 向けのアプリです。このページの「App Store で開く」から入れます。

ログインは必要ですか？

フィード、通知、カレンダーなどの主な機能は、サインインなしで使えます。Apple でサインインが要るのは、マップへの投稿と「今日の運試し」だけです。

公式のアプリですか？

いいえ。各カードゲームの権利者や販売店とは関係のない、個人が開発した非公式のアプリです。掲載している情報は、各販売店の公開情報をもとにしています。応募・購入の前に、必ず各販売店の公式ページで最新の内容を確認してください。

無料で使えますか？

基本機能は無料です。商品フォローの数や通知の速さなどを広げる、有料の Pro もあります。

  • 各カードゲームの権利者や、販売店とは関係のない、個人が開発した非公式のアプリです。

この作品の記録

  • Claude API から Gemini API（gemini-3.1-flash-lite）へ移行した：16 か所の呼び出しを 1 つの関数にまとめた — Anthropic の利用上限で予定外の課金が出たため Gemini へ移行。モデルの選び方（廃止予定日）、呼び出しの一本化、Web 検索の回数上限が無い問題への回路遮断器、止めるスイッチの記録。
  • Xcode 15.2 で Firebase 12 が使えない（Swift 6.0 必須）：Firebase 11.4.0 と AdMob 11.5.0 に固定した理由 — 古い Mac の Xcode 15.2 では、Firebase 12 以降と 11.12.0 以降は Xcode 16.2 が必須、AdMob 11.6.0 以降は MarketplaceKit で Xcode 15.3 が必須。Exact Version で固定した記録。
  • ITMS-91064「無効なバイナリ」：NSPrivacyTracking が true なのに NSPrivacyTrackingDomains が空だった — ビルドが Apple の自動審査で ITMS-91064 により却下された。NSPrivacyTracking が true で、NSPrivacyTrackingDomains が空の配列だったのが原因。ドメインを補った経緯と、確認できていないこと。
  • 一括処理が「全記事」に当たった：書く前に数える、テストは壊して確かめる — 記事の状態をまとめて直す処理が、全記事に当たり、18件が誤って表示に戻った。履歴から戻した経緯と、テストが効くかを、規則を1つずつ外して確かめた記録。
  • 「9種セット」を中身ごとに分けて、偽の商品が80個できていた — ポケモンカードの9種セットは1つの商品なのに、中身ごとに分けて、実在しない商品が80個できていた。入口を止め、親22件を戻し、子190件を外し、偽の商品を消した記録。
  • Firebase Auth：アプリを完全に終了すると、匿名アカウントが量産された（currentUser の復元待ち） — 「アプリを落とすと、また Apple のサインインを求められる」。管理画面を開くと、19人中17人が使い捨ての匿名アカウント。起動直後に currentUser を同期チェックしていた競争を、addStateDidChangeListener で直した記録。
  • 「重複は実質ゼロ」と数えたのに、監査は112組を出していた — 重複を統合する処理が、毎晩、先頭のジャンルの途中で時間切れになっていた。「ゼロ」と数えた自分の測り方が間違っていた。持ち回りに直して112組を0組にした記録。
  • 「取れた」と読んでいたのは、ただの案内ページだった：3日間、商品が0件 — ポケモンセンターの取得が3日間ずっと商品0件だった。安い設定が返した2,410バイトの「JavaScriptを有効に」ページを、成功と読んでいた。判定を1か所に集めた記録。
  • 確認できなかったときに、通していた：「fail-open」が転売品を招いた話 — 「定価を確認できなかったら通す」という設計に、検索の1日上限という盲点があった。「知らなかった」と「調べられなかった」を区別して直した記録。
  • 一度だけ生まれた誤字が、店ごとに増えていった：「30th SEREBRATION」の件 — 誤字の商品が一度作られると、既存の商品として再利用され、店ごとに増える。13記事を直し、短い見出しを完全一致で拾う予防を入れ、保険のチェックの限界まで確かめた記録。
  • 「しょうがない」を測り直したら、取得の費用は8分の1だった — 「イオンとあみあみは費用が重くて縮められない」は、古い単価に基づく思い込みだった。3つの取得設定で同じページを比べて、描画が丸ごと無駄だと分かった記録。
  • App Store 審査で「Guideline 2.1 Information Needed」が届いた：求められた6つ — 初めての審査で届いたのは、不合格ではなく Guideline 2.1「Information Needed」だった。求められた六つ（実機の画面収録、目的、外部サービスの一覧など）と、前に直したこととのつながり。
  • App Store の審査で止まった四つ：iPad のスクショ、ITMS-91064、アカウント削除、投稿の通報 — iPad スクリーンショットの要求、自動検査の ITMS-91064（NSPrivacyTrackingDomains が空）、アカウント削除（5.1.1(v)）、投稿の通報（1.2）。審査に出す手前で止まった四つと、その直し方。
  • 「9種セット」の正体は御三家9商品だった：同じ商品なのに、決して一致しなかった — 他のまとめサイトと突き合わせたら、抽選の表示は54%だった。商品の取り違え、比べ方の左右非対称、記事IDの穴。カバー率を91%にした記録。
  • iOS アプリが固まって強制終了される（0x8BADF00D）：SwiftUI の計算プロパティが毎回走っていた — 実機のログにあった 0x8BADF00D（watchdog）。951件の記事を、画面を描き直すたびにメインスレッドで数え直していた。原因の特定と、バックグラウンドで計算する形に直した記録。
  • TestFlight にビルドが来ない：Xcode Cloud の月25時間を使い切っていた（最初の診断は誤りだった） — 「[ci skip] が原因」という最初の診断は、時系列が合わず誤りだった。Xcode Cloud の無料枠（月25時間）を使い切った本当の原因と、開始条件を絞る直し方の記録。
  • 「減るはず」が、二度外れた：AIへの問い合わせを削る話 — トレカ情報アプリで、AI への問い合わせを減らそうとした記録。45%減るはずが4.5%、配備したのに束ねが0回。数え直して見つかったことを、コミットの数字で書いた。
