作りながら考えたことの記録。
勘で直す前に、まず測る——という話が多いです。

実際の作業の記録（コミットと、手元で測った数字）から書いています。作品ごとに、まとめました。

テーマ別に読む

本数が多いので、はじめての方は、次のテーマから選ぶと読みやすいです。

数えて、直した

勘で直す前に、まず数える。費用と監査の数字を疑って、測り直した記録。

  • Firestore の費用を円で出したら、読み取りの 91% が 1 か所だった：キャッシュを入れても効かなかった理由
  • Gemini の費用を削る前に、計器を疑った：単価・内訳・キャッシュの 3 つが壊れていて、キャッシュの条件は測り直すと変わっていた
  • 「しょうがない」を測り直したら、取得の費用は8分の1だった
  • 「重複は実質ゼロ」と数えたのに、監査は112組を出していた
  • 監査 61 本を総点検して見つけた 4 つ：朝 4 時に 51 本が固まり、鍵の期限は 55 秒で、定価の補完は「入れない」と決めた
  • 関門を直しても、すでにあるデータは直らない：「もう試した」印・URL の目印・対応表の 3 つの実例
  • 「次回へ」と出続けていた 25 本の点検は、一度も走っていなかった：3 つの時間予算を、同じ開始時刻から数えていた
  • 「減るはず」が、二度外れた：AIへの問い合わせを削る話

静かに壊れていた

エラーが出ないまま、本物が消えていた、または読めていなかった失敗の記録。

  • 「取れた」と読んでいたのは、ただの案内ページだった：3日間、商品が0件
  • 「確認済み」の印が付いていたのに、リンク先を一度も読めていなかった：t.co の中継ページ
  • 本物の抽選を、静かに捨てていた 4 つの実例：正規表現・年のない日付・まとめて聞く・null
  • 候補は見つかっていたのに、答えを読む所で毎回落ちていた：200 トークンで切れた URL と、ハイフンで 400 になる検索
  • 先着が始まった瞬間、サイトが順番待ちのページになる：8,000 バイトの関門を、15KB の案内ページがすり抜けた
  • 通知は取り消せない：直近 72 時間の通知の 19% が誤通知で、関門が通知の「後」に効いていた
  • 表示中の記事のリンク先を、実際に開いて確かめた：約 60 件の間違いと、最初の点検が間違えた 3 つのこと

名前と商品の取り違え

同じ名前、同じリンクが、別のものを指していた。商品と店の取り違えの記録。

  • 1 つの記事を商品ごとに分ける処理で起きた 3 つの取り違え：子が親になり、共有リンクが別の店を指し、名前が 2 つの商品のものだった
  • 「同じ応募ページ」なら「同じ店」と決めつけていた：店名が別の店になった記事 52 件
  • 公式の一覧から、「作品名だけの商品」が 393 件できていた：商品名の欄に、商品の形は入っていなかった
  • 商品のジャンルを、公式カタログで直した：下見を 3 回やって、13 件から 4 件に絞った
  • 「これベイブレードじゃん」が、関門を入れても戻ってきた：弾いた値が、別の形で漏れた
  • 「後から掃除するから大丈夫」が、入口の不具合を隠していた：商品が毎日 400 件そっくり作り直されていた
  • 一度だけ生まれた誤字が、店ごとに増えていった：「30th SEREBRATION」の件
  • 「9種セット」を中身ごとに分けて、偽の商品が80個できていた

監視と定期処理

先着の監視、同時実行の枠、配備と再実行。動き続ける処理の設計の記録。

  • 「1 分おき」の監視は、1 件あたり 10 分に 1 回だった：速くする前に、見直しの間隔と、通知が届いた数を数えた
  • 全部を速く見られないとき、何を速くするか：427 弾のうち人気の 128 弾を速く回し、予算を超えたら自分から譲る
  • 同時実行の枠を増やす前に見るもの：2 コアのサーバーで、枠を 8 から 14 にした判断と、半分間違っていた前の結論
  • 配備のたびに、日次の処理が丸ごと走り直していた：48 時間で 477 回、その日の Gemini 費用の 46.6%
  • X 監視の漏れ 4 つ：検索に出ない投稿、持ち主が変わるアカウント、店を探せない検索、止まった後の取り戻し
  • 競合サイトと突き合わせて、取りこぼしを数えた：最初の「カバー率 23%」は測り方の間違いで、本当は 49% だった
  • 自分で作った仕組みが、自分を傷つけた 4 つの記録：要約が条件を捨て、1 つの未定義が保存を止め、点検が本番の IP を閉め出された

iOS アプリと基盤

サーバーの移行、iCloud、広告、審査、ビルド。アプリとその土台の、実際に起きたことの記録。

  • Cloud Functions から月 4,300 円のサーバーへ移した：1 日 3,700 円の課金、EEA で全滅した Yahoo!、移行で踏んだ 5 つの罠
  • 「iCloud が新しければ取り込む」の関数が、何も比べていなかった：応募の記録が 20 件から 1 件になりうる
  • 広告が出ないと、実機チェックの 25 項目が止まった：開発者モードだけテスト広告を使い、賞品名を直書きしない
  • iOS アプリが固まって強制終了される（0x8BADF00D）：SwiftUI の計算プロパティが毎回走っていた
  • TestFlight にビルドが来ない：Xcode Cloud の月25時間を使い切っていた（最初の診断は誤りだった）
  • ITMS-91064「無効なバイナリ」：NSPrivacyTracking が true なのに NSPrivacyTrackingDomains が空だった
  • Xcode 15.2 で Firebase 12 が使えない（Swift 6.0 必須）：Firebase 11.4.0 と AdMob 11.5.0 に固定した理由
  • App Store の審査で止まった四つ：iPad のスクショ、ITMS-91064、アカウント削除、投稿の通報
  • App Store 審査で「Guideline 2.1 Information Needed」が届いた：求められた6つ
  • Firebase Auth：アプリを完全に終了すると、匿名アカウントが量産された（currentUser の復元待ち）

ゲームの設計と測定

釣り合いを、AI 同士の対局や自動の試行で測って決めた記録。

  • 寝返り将棋のルールを、AI 同士の対局で決めた：効いた 1 つの変更と、壊れた 6 つの案
  • オンライン対戦は、端末の言うことを何も信用しない：手・持ち時間・勝敗を、サーバーが決める設計
  • 穴子がデカすぎた話
  • 「山は89%で落ち着く」は誤りだった：測定のほうが間違っていた話
  • 10秒ピッタリのランキングを、公平にする：小数3桁・同着・書き込み回数
  • 診断を12問にしたら、結果はどこまで変わるのか

  • 静的サイトを置く場所を、公式の規約で比べる：Cloudflare Pages・Netlify・Vercel・GitHub Pages・Firebase Hosting
  • Claude API と Gemini API を、公式の数字で比べる：小さいモデルの値段・Web検索・上限・廃止予定
