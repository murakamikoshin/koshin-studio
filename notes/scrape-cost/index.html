「しょうがない」を測り直したら、取得の費用は8分の1だった

トレカダッシュ 開発の記録 ／ 2026年10月

iOS アプリ「トレカダッシュ」は、通販サイトなどの販売ページを定期的に見に行って、抽選や先着の情報を集めています。ページの取得は、外部のサービス（Scrape.do）を通して行っていて、取得の設定ごとに、使うクレジットが違います。あるサイトについて、「これはしょうがない」と思っていたことを、測り直したら、3 倍速く、使う量は 8 分の 1になりました。コミットの記録で書きます。

このサイトには、トレカダッシュの作品ページはまだありません。ここに書くのは、開発の記録です。金額は書かず、クレジットの数だけを書きます。

「しょうがない」の理由は、費用だった

イオンスタイルオンラインと、あみあみの 2 サイトは、取得の間隔を縮められない、と考えていました。理由は、取得にかかる費用が重いこと。つまり、古い単価を前提にした結論です。それを、もう一度、測ってみることにしました。

3 つの設定で、同じページを取った

取得の設定は、3 段階あります。単純に取る（1 クレジット）、ブラウザで描画してから取る（render、5 クレジット）、さらに強力な経路で描画して取る（super＋render、25 クレジット）。イオンの一覧ページを、この 3 つで取って、中身を比べました。2 ページを、それぞれ 3 回、くり返しています。

設定クレジットサイズ（バイト）商品価格
単純に取る1649,73420 件25 件
render5663,02620 件25 件
super＋render25669,51020 件25 件

3 つとも、取れた商品も価格も、まったく同じでした。つまり、描画（render）は、まるごと無駄だったことになります。1 クレジットで足りるものに、25 クレジット払っていました。

直し方

  • 安い設定から先に試す。イオンは、まず単純に取ります。先着の開始時に出る「アクセス集中」のページが返ってきたときだけ、自動で強い設定に切り替えます。
  • 間隔を、15 分から 5 分に。5 分おきは、1 日 288 回です。2 ページなので、576 クレジット。前は、1 日に約 4,600 クレジットでした（コミットの記載です）。3 倍速くなって、使う量は約 8 分の 1です。
  • あみあみにも、同じ実測の結果を当てた。描画を外して、1 回あたり 5 クレジットから 1 クレジットに。1 日に約 1,200 クレジットの節約です。

ただし、あみあみの間隔は、15 分のままにしました。その日、タイムアウトを 2 回出していて、1 回の実行が 284 秒もかかっていたからです。取得全体も混み合ってきていたので、触らないと決めました。測ったのは「描画が要るか」で、「間隔を縮めても大丈夫か」ではありません。

分かったこと

「しょうがない」は、いつ測った数字に、もとづいているか。
  • 古い結論は、測り直す。単価も、設定も、サイトの作りも、変わります。「イオンはしょうがない」は、測ったら、そうではありませんでした。
  • 強い設定は、「念のため」で入れがち。必要かどうかは、結果を比べれば分かります。同じ結果が出るなら、安いほうで足ります。
  • 一つ直したら、他の条件も確かめる。同じ測定で、あみあみの設定も直せましたが、間隔は別の事情（タイムアウト）があるので、そのままにしました。

この記事の数字は、コミット（2026年9月7日）の記録から取りました。「4,600」は、コミットの記載で、25 クレジット × 2 ページ × 96 回（15 分おき）の計算（4,800）とは、少しずれています。

  • 「9種セット」の正体は御三家9商品だった — 同じアプリの、突き合わせの記録

ほかの記録

  • Claude API から Gemini API（gemini-3.1-flash-lite）へ移行した：16 か所の呼び出しを 1 つの関数にまとめた — Anthropic の利用上限で予定外の課金が出たため Gemini へ移行。モデルの選び方（廃止予定日）、呼び出しの一本化、Web 検索の回数上限が無い問題への回路遮断器、止めるスイッチの記録。
  • Xcode 15.2 で Firebase 12 が使えない（Swift 6.0 必須）：Firebase 11.4.0 と AdMob 11.5.0 に固定した理由 — 古い Mac の Xcode 15.2 では、Firebase 12 以降と 11.12.0 以降は Xcode 16.2 が必須、AdMob 11.6.0 以降は MarketplaceKit で Xcode 15.3 が必須。Exact Version で固定した記録。
  • ITMS-91064「無効なバイナリ」：NSPrivacyTracking が true なのに NSPrivacyTrackingDomains が空だった — ビルドが Apple の自動審査で ITMS-91064 により却下された。NSPrivacyTracking が true で、NSPrivacyTrackingDomains が空の配列だったのが原因。ドメインを補った経緯と、確認できていないこと。
