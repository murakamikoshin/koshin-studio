X の投稿に貼られた応募リンクを開いて、締切や受付終了を確かめる処理がありました。「締切が違う」という報告を調べると、締切どころか、**リンク先を一度も読めていません**でした。しかも、「確認済み」の印が付いていました。

## 原因：t.co は、ブラウザのふりをすると、転送しない

X のリンクは `t.co` を通ります。普通は、開くと本来のリンク先へ転送されます（301）。ところが、**ブラウザの User-Agent を付けて開くと、転送されず、JavaScript で飛ばす約 500 バイトの中継ページが返ります**。

読み取りの 2 か所が、ブラウザの名乗りを付けて「転送に従う」設定だったので、最後の URL は `t.co` のまま、本文は中継ページの HTML でした。ブラウザの名乗りを足したのは 8 月 6 日。その副作用でした。

## どれくらい読めていなかったか

| 調べたこと | 結果 |
|---|---|
| `t.co` を持つ表示中の記事 | 220 件 |
| そのうち、中継ページが返った | 220 件（全部） |
| 実は閉じたフォームなのに、表示中 | 9 件 |

毎日動く「締切が空の記事を直す」処理が、「対象 126 件、更新 0 件」を毎日繰り返していたのも、手がかりでした。

## 直し方

```text
1. 名乗りなしで t.co を開く。redirect: "manual" で、最初の転送先だけ受け取る
2. 転送先が返れば、それを使う
3. 中継ページなら、<meta http-equiv="refresh"> を読んで、本当の転送先を取る
4. その転送先を、今度はブラウザの名乗りありで開く
```

誤って付いた「確認済み」の印は、195 件から外して、確認と締切の再抽出を手で実行しました（更新は 0 件 → 14 件）。

## 分かったこと

- 「確認した」の印は、読めたときだけ付ける。
- 外のページを読んだら、目的のページかを確かめる（最後の URL が短縮 URL のままではないか）。
- 「更新 0 件」が毎日続くのは、異常のサインかもしれない。
